# しゅがけストーキング

しゅがけ（Sugar Cage）IP のレトロ風アクション。単一 HTML / 外部依存なし。

実機テスト: https://ghbe2.github.io/sc_stalking/

---

## いま入っているもの: 路地の画面だけ

ミナリが路地を上へ走る。縦スクロール・5レーン・奥行なし。

### 操作

画面の**左半分／右半分をタップ**すると、その方向へ **1列ずつ**移動する。長押しで連続移動。
デスクトップは ← → キー。

### ルール

| | |
|---|---|
| 子供 | 前から歩いてくる（遅い）。触れるとハート -1 |
| 男 | 前から歩いてくる（速い）。触れるとハート -1 |
| 女 | 横切ってくる。触れると叫ばれて、どこかの列に**監視**がつく |
| 監視 | その列を見張る。監視列に居続けると発見され、トウカの画面へ |
| 空き缶 / おにぎり | 拾うとスコア |
| マンホール | 飛び込むと**落下**へ。おにぎりを拾ってハートを回復し、次のステージへ |

- **ハート3個。尽きたら GAME OVER。**
- 生き延びているだけでスコアが入り、**粘るほど毎秒のレートが上がる**（+10/s → +55/s）。
- 時間が経つほど人混みが詰まり、歩いてくる連中が速くなる（x1.0 → x1.7）。
  **落ちているアイテムは速くならない。**
- 監視は徐々に増える。**最大4列まで**——1列は必ず空ける（難易度の問題にとどめ、理不尽にしない）。
- 監視は**画面の上に小さな目が出るだけ**（ミナリの視線の先）。列は塗らないし、ゲージも出さない。
  **気づけなかったらアウト**、という見せ方にしている。
- 「見られている」時間はミナリ側に1本。列を移っても引き継ぐので、監視列を渡り歩いても逃げられない。
- 開幕は約1秒、誰も来ない。人は必ず画面の外から降りてくる。

### この画面の役割

**路地は生存に徹する。** 危険を冒してスコアを稼ぐのはトウカフェーズの役目。
唯一の判断は「**いつマンホールで抜けるか**」。粘るほどスコアは伸びるが、生還率は落ちる。

## 落下の画面

マンホールに飛び込むと縦穴を落ちる（約5秒）。**上下が路地と逆**で、おにぎりが下から昇ってくる。
拾うとハートが1個戻る（満タンならスコア）。

**落下中はレーンを使わない。** 押している方向へ緩慢に流れ、指を離しても慣性で少し流れ続ける。
移動はかなり鈍く、押しっぱなしでも 1 秒で 14px しか動かない（画面幅は約 138px）。

おにぎりは3個で位置は完全ランダム。**狙っても取れるのは1個がせいぜい**（20回試して
0個が4回・1個が8回・2個が6回・3個が2回）。放っておけば平均0.35個。
回復は当てにするものではなく、拾えたら儲けもの、という重みにしてある。

**ハートを取り戻せるのはここだけ。** 監視に見つかってトウカへ行くとこの画面を通らないので、
安全な道を選んだ者だけが回復する。低リスク低リターン／高リスク高リターンを、
点数だけでなく体力でも表している。

落ちた先は下水。

## 下水の画面

横スクロール。ミナリは自動で右へ走り、**入力は1つだけ**。

| | |
|---|---|
| 押しっぱなし | しゃがむ（同時にジャンプを溜める） |
| 放す | 溜めたぶん跳ぶ |

- **蝙蝠の群れ** — 縦に積まれていて、跳んでも上は抜けられない。**しゃがむしかない**
- **穴** — 足場が切れている。跳んで越える。落ちるとハート -1 で次の足場から再開
- **はしご** — 天井から下がっている。**跳んで掴めば地上へ戻る**（ステージが1つ進む）
- **振動** — 着地するとトウカに位置が伝わる。積もりきるとトウカフェーズへ

### 潜るか、上がるか

はしごは一定距離ごとに現れる。**掴むかどうかは自分で決める。** 見送って潜るほど地形は
険しくなり（穴が広く・多く、蝙蝠が増え、走りも速くなる）、そのぶん跳ぶ回数が増える。

**跳ぶこと自体がコスト。** トウカはナマズなので、水と地面を伝わる振動を直接感知する。
しゃがみは無音、着地は響く。しかも**大きく溜めたぶんだけ重く響く**（溜めなし +5 /
最大溜め +26）ので、「必要なぶんだけ溜める」が上手さになる。地に足がついている間だけ
振動は静まっていく。

抜けずに潜り続けると、必要最小限で跳んでも約57秒、余分に溜めると約47秒でトウカに掴まる。
1本目のはしごで上がれば7秒、3本目で24秒、6本目で43秒。

はしごは**穴からも蝙蝠からも離れた平地にだけ**置かれる。そうしないと穴を越えるための跳躍で
事故的に掴んでしまい、「自分で選んだ脱出」にならないため。

**しゃがみ続ければ必ず跳ぶ**ので、いつ放すかがそのまま判断になる。蝙蝠の下でやり過ごした
溜めは、直後の穴でそのまま活きる。逆に穴を跳んだ直後に蝙蝠が来る配置では、着地して
すぐ伏せ直さなければならない。

溜めなしで高さ22px・距離33px、最大溜めで高さ64px・距離58px跳ぶ。穴の幅は24〜46px。
**保証則として「跳べる幅」「踏み切りと着地の足場」「穴どうしの間隔」「群れが跳び越えられない
高さか」「はしごが跳ばないと届かず最大溜めなら届くか」を機械的に検査**している。

蝙蝠を抜けきる前に放すと当たる。当たり判定を抜けるまで（約4px＝0.07秒）我慢する必要がある。
長く押し続けるぶんには当たらないが、そのぶん着地が重く響く。**早く放せば蝙蝠、
溜めすぎれば振動**、という両側からの締め付けになっている。

通算時間はリセットされないので、ステージを重ねるほど難しくなる。

## これから作るもの

- **トウカフェーズ**（高リスク高リターン。捕まったら即 GAME OVER、生還すればボーナス）
- **下水からの脱出**（動き未定。ここにも回復の機会を置く予定）

画面の切り替えは `enterAlley()` / `enterFall()` / `enterSewer()` / `finish(how)` に集約してある。
いまの周回は 路地 → 落下 → 下水 → 路地（ステージ+1）。

## 開発用

画面右上の `≡` から:

- **seed** — 同じコースを再現する
- **開始ステージ** — 押すたび 1〜8 を巡回。選ぶと通算時間もそのぶん進んだ状態で始まるので、
  終盤の難易度をすぐ試せる（タイトルにも表示される）
- **落下を見る** / **下水を見る** — その場でその画面へ飛ぶ
- **DEBUG** — 内部数値の表示

タイトル画面の右下にビルド番号（例 `0812A`）が出る。実機で古いキャッシュを見ていないか、
ここで確かめられる。更新したら `index.html` 冒頭の `BUILD` を上げること。

数値はすべて `CONFIG` に集約してあり、`ramp`（人混み・点の入り）と `watchRamp`（監視）は
独立した時計で走る。
